# 역할 3, UI와 UX 적대적 리뷰

## 1. 총평

가장 치명적인 문제는 첫 패널 설치를 배우지 못한 학생에게도 스폰 10초 뒤 다음 미션을 보여 주는 온보딩이다. 설치 장소를 찾는 시간과 설명을 읽는 시간이 게임의 소비 시간으로 처리되고, 물 원정에서는 귀환 방향을 알려 주지 않으며, 건설 화면은 자원이 없어도 가능하다고 말한다. 모바일 가로에서는 고정 폭 HUD가 미션을 덮고 모듈 목록 일부가 화면 밖으로 나간다. 이 상태의 데모는 자원 배분을 이해하는 학생보다 개발자가 옆에서 조작을 설명받는 학생에게 유리하다. 교육 효과를 주장하려면 행동 완료에 따른 안내, 귀환 표시, 위험의 남은 시간, 실제 가동 여부부터 고쳐야 한다.

검토 완료일은 2026-10-18이며 최종 대조 커밋은 `5315135`다. 제공된 플레이테스트 기록은 2026-10-17 기준이다. `docs/GDD.md`를 먼저 읽고, `docs/CONTRACT.md`, 클라이언트 13개 파일 전체, Config의 문구와 관련 서버 판정을 대조했다. 검토 중 다른 작업에서 갱신된 기획서와 테스트도 최종 결과에 반영했다. Roblox Studio, 실제 화면, 터치 입력, 네트워크는 검증하지 않았다. 아래 좌표는 코드로 계산한 배치이며 실제 화면 측정값이 아니다. 이번 작업에서 작성한 파일은 이 보고서뿐이다.

최종 검증 명령 `lune run tests/run.luau`에서 Simulation 30개와 ServerSmoke 259개 확인이 통과했다. 서버 스모크의 실패, 스레드 오류, 경고는 모두 0이고 전체 종료 코드는 0이다. 이 테스트는 클라이언트의 가독성과 조작 성공을 검증하지 않는다.

## 2. 발견 사항, 심각도 순

### F01. 첫 행동을 배우지 않아도 10초 뒤 안내를 지운다

- 심각도: 치명
- 근거: `src/shared/Config.luau:29,174,251`, `src/shared/Simulation.luau:479-493`. 설치 안내는 `day < 2`일 때만 유지된다. `src/server/GameClock.luau:63-70`에서 첫 틱은 시작 10초 뒤다. 설치 안내는 장소 이름만 말하며 홀드 시간과 위치 표시가 없다. `src/server/DevMap.luau:118`의 설치 파트는 기지 원점에서 약 36 studs 떨어져 있고 기본 프롬프트 거리는 12다.
- 반례 시나리오: 처음 접속한 14살 학생이 스폰 후 8초 동안 자원과 화면을 읽고 주변을 돌려 본다. 설치 파트의 12 studs 안에도 들어가기 전에 2일차가 되어 로버 안내로 바뀐다. 학생은 발전을 시작하지 않은 채 출발하고, 귀환 후 에너지가 부족한 이유를 설명받지 못한다.
- 목적 손상: 학습 완료를 날짜 경과로 오인한다. 심사위원의 첫 행동이 패널 설치 대신 길 찾기가 되고, 원래 의도한 발전과 소비의 관계를 경험하지 못한다.
- 구체적 제안: 첫 설치 안내의 완료 조건을 `panelsInstalled >= 3`으로 바꾸고 날짜 조건을 제거한다. 현재 목표 파트 하나에만 테두리와 거리 표시를 붙인다. 문구는 `태양광 설치대에서 패널 3장을 설치하세요. E를 2초 누르세요`로 바꾼다. 10초간 행동이 없으면 같은 목표를 더 선명하게 표시하고 단계를 넘기지 않는다. 설치 성공마다 `1/3`, `2/3`, `3/3`을 갱신한다. 팀 공통 설치 수와 개인 조작 설명은 분리한다.
- 예상 작업량: M, 반나절

### F02. 모바일 가로에서 다음 할 일이 HUD에 덮이고 버튼도 축소된다

- 심각도: 치명, 모바일 데모 기준
- 근거: `src/client/HUD.luau:159-167,212-216,241-278`. 자원 폭 236, 미션 폭 460, 오른쪽 패널 폭 260이 화면 폭에 따라 재배치되지 않는다. 모듈은 y=300에서 시작해 높이 약 194다. 터치 배속 버튼은 x=`화면 중앙+238`, 폭 72다. `src/client/SiteSelectUI.luau:154-164`는 전체 UIScale로 작은 화면에 맞춘다. 아래 배치 계산 표 참조.
- 반례 시나리오: 844x390 가로 화면으로 들어온 학생이 상단 미션을 읽으려 한다. 미션의 왼쪽 56px은 자원 영역과, 오른쪽 80px은 패널 영역과 겹친다. 배속 버튼도 오른쪽 정보 패널과 겹친다. 모듈 목록은 화면 아래로 최소 104px 넘는다. 착륙지 선택 버튼은 높이가 33px로 줄어든다.
- 목적 손상: 터치 기기에서 안내를 2초 안에 찾을 수 없고, 건설 상태를 비교할 수 없다. 학생의 선택보다 화면 크기가 성공에 영향을 준다.
- 구체적 제안: 폭 1000px 미만에서는 별도 배치를 쓴다. 자원은 안전 영역 상단에 높이 44px의 3열 한 줄, 미션은 그 아래 높이 60px 이내, 날짜와 패널 수는 하나의 보조 행으로 합친다. 모듈 목록은 44px 이상 버튼으로 여는 서랍으로 접는다. 배속은 보조 행 안에 넣는다. 착륙지 카드는 최소 폭 260px의 가로 스크롤로 바꾸고 버튼 높이 44px, 본문 17px를 유지한다. 전체 UIScale로 본문을 줄이지 않는다. 1280x720, 844x390, 667x375에서 각각 검사한다.
- 예상 작업량: M, 반나절

### F03. 물을 채운 순간부터 귀환 방향과 하역 동작이 사라진다

- 심각도: 높음
- 근거: `src/client/RadarUI.luau:60-106`은 IceSites만 표시한다. 기지, 물탱크 표시는 없다. `src/shared/Simulation.luau:488-493`은 탑승 여부를 모르므로 운전 중에도 탱크가 비어 있으면 탑승 안내를 유지한다. 만충 뒤에는 `MISSION_TEXTS.firstWaterTrip`의 채취와 하역을 합친 문장을 표시한다. `src/server/WaterLoop.luau:77-103`에서 하역은 물탱크 근처에 로버가 있어야 하고, 사람이 물탱크 프롬프트도 작동시켜야 한다.
- 반례 시나리오: 학생이 얼음에서 물 40을 채우고 카메라를 돌린다. 레이더에는 여전히 얼음 점 세 개만 보인다. 귀환 후 로버를 기지 옆에 세워도 기지 물은 증가하지 않는다. 자동 하역을 기대한 학생은 다시 얼음으로 가거나 빈 탱크가 아닌데도 채취를 반복한다.
- 목적 손상: 자원을 확보해도 다음 행동을 찾지 못한다. 원정의 성취가 귀환 길 찾기와 수동 하역의 발견 여부에 묻힌다.
- 구체적 제안: 탱크가 0보다 크면 레이더 주 목표를 `기지 물탱크`로 전환하고, 사각형 기지 아이콘과 거리, 화면 밖 방향 화살표를 표시한다. 안내를 `물 40 확보. 기지 물탱크로 돌아가 하역하세요`로 바꾼다. 로버가 물탱크 표면에서 15 studs 안이면 `물탱크에 다가가 E로 하역하세요`로 전환한다. 첫 하역 때 기지 물 증가와 탱크 0을 같은 위치에서 2초간 보여 준다.
- 예상 작업량: M, 반나절

### F04. 자원 수치는 보이지만 원정을 떠날 시점과 실패까지 남은 시간은 보이지 않는다

- 심각도: 높음
- 근거: `src/client/HUD.luau:74-85,315-321,348-356`. 감소는 순증감의 빨간 글씨뿐이며 재고 위험에 따른 색 변화가 없다. 경고 배너는 0이 된 이후에만 뜬다. `src/shared/Simulation.luau:278-281`의 순증감은 마지막 틱 실적이고 다음 날 예측이 아니다. 정수 반올림 때문에 일조율 85%, 패널 3장, A 가동 시 실제 에너지 순감소 -0.45가 `0/일`로 표시된다.
- 반례 시나리오: A와 B를 운영하는 학생이 `Water 19`를 넉넉하다고 판단한다. 정상 가동 중 물 소비는 하루 4이므로 재고는 4.75일분, 다음 틱까지 10초가 남았다면 약 50초 뒤 0이다. GDD의 왕복 약 60초보다 짧다. 식량 3에서도 사전 경고가 없고, 물이 처음 0인 틱에는 부족 1일째라 실패까지 두 틱, 1배속 최대 약 20초만 남는다.
- 목적 손상: 선택의 미래 영향을 계산하라는 게임이 핵심 계산을 학생에게 숨긴다. 실패 직전 알림은 예방을 위한 의사결정 기회가 되지 못한다.
- 구체적 제안: 실제 다음 날 생산과 소비로 예측치를 따로 계산하고 `현재 소비 기준 물 약 4.8일분`을 표시한다. 생산이 소비 이상이면 `유지 가능`으로 표시한다. 작은 증감은 소수 한 자리로 보여 -0.45를 0으로 만들지 않는다. 원정 권고는 `물 <= 일일 소비 x (예상 왕복 틱 수 + 2)`에서 켠다. 식량 고갈 3일 전 경고에 더해 농장 건설 5일과 여유 2일을 반영한 7일분 시점에 농장 건설을 유도한다. 0 이후에는 `물 부족 1/3일, 실패까지 2일`과 현재 배속 기준 남은 초를 함께 표시한다. 정확한 초를 쓰려면 서버의 다음 틱 시각을 전달해야 한다.
- 예상 작업량: M, 반나절

### F05. 시설이 멈춰도 HUD와 패드는 계속 가동 중이라고 말한다

- 심각도: 높음
- 근거: `src/server/GameFlow.luau:90-93`은 전력 정지로 바뀔 때 토스트를 한 번 보낸다. `src/client/HUD.luau:297-312`, `src/client/PadSignUI.luau:130-149`는 `modulesStalled`를 읽지 않고 status가 active이면 계속 가동 중으로 표시한다. `src/shared/Simulation.luau:206-223`에서는 물이 부족해도 농장 생산이 0이 되지만 이 사유를 나타내는 표시가 없다.
- 반례 시나리오: 농장을 완공한 학생이 채취 중 전력 정지 토스트를 놓친다. 귀환해 초록 HUD의 `가동 중`과 하늘색 농장 표지판을 보며 식량이 생산된다고 믿는다. 물이 부족해 농장이 멈춘 경우에는 전력 정지 토스트조차 없다.
- 목적 손상: 비용, 유지 자원, 생산의 인과관계를 거꾸로 가르친다. 학생은 시설을 완공하면 식량이 자동으로 보장된다고 오해한다.
- 구체적 제안: 완공 여부와 실제 운영 여부를 별도 필드로 표현한다. HUD와 표지판에 `전력 부족, 정지`, `물 부족, 식량 생산 0`을 지속 표시하고 복구 시 즉시 해제한다. 상태 색만 바꾸지 말고 사유와 생산량을 적는다. 정지 진입 시 1회 경고음, 복구 시 1회 짧은 확인음을 사용한다. 전력 경고는 관측된 정지 틱, 물 경고는 농장의 실제 생산 여부에 근거해야 한다.
- 예상 작업량: M, 반나절

### F06. 건설 가능은 자원 충족을 뜻하지 않아 첫 착공부터 화면이 거짓말한다

- 심각도: 높음
- 근거: `src/shared/Simulation.luau:120-126`에서 available은 선행 시설 조건만 반영한다. `src/client/PadSignUI.luau:17-21,148`은 이를 `건설 가능`으로 표시한다. `src/server/Construction.luau:42`도 자원과 무관하게 프롬프트를 켠다. 실제 비용 검사는 누른 뒤 `src/shared/Simulation.luau:318-330`에서 수행한다. 부족 안내는 차액 대신 총 필요량을 말한다.
- 반례 시나리오: Energy 63, Water 19인 학생이 초록 `건설 가능`인 A 패드에서 건설을 누른다. 물 20 필요라는 토스트를 보고도 물이 1 부족한지 20을 더 모아야 하는지 다시 HUD를 찾아 계산한다. B 해금 후에도 같은 시행착오가 반복된다.
- 목적 손상: 화면의 가능 표시를 믿을 수 없어지고, 자원을 계획하기보다 계속 눌러 보는 행동을 학습한다.
- 구체적 제안: 선행 조건 충족만으로는 `해금됨`을 표시한다. 비용도 충족하면 `착공 가능`으로 바꾼다. 자원이 부족하면 `물 1 부족`처럼 차액을 표지판과 프롬프트에 적는다. 착공 직전에는 비용, 착공 후 잔량, 유지 소비를 함께 보여 준다. A 예시는 `전력 60, 물 20 사용, 완공 후 매일 전력 3, 물 1 소비`다. 유효한 착공은 기존 0.5초 홀드로 실행한다.
- 예상 작업량: M, 반나절

### F07. 시작을 누르기 전 시간이 흐르고 타이틀은 승리 조건도 잘못 설명한다

- 심각도: 높음
- 근거: `src/client/TitleUI.luau:58-61`은 `90일을 살아남으세요`라고 표시한다. 실제 승리는 C 완공 즉시이고 90일 생존만으로는 실패다. `src/client/Main.client.luau:61-62,78-80`에서 시작은 로컬 타이틀만 닫는다. `src/server/LandingSite.luau:96-108`은 첫 권한자 지정부터 30초 타이머를 시작하므로 타이틀에서 쓰는 시간도 포함된다.

- 구체적 제안: 상호작용 화면은 CoreUISafeInsets를 기준으로 통일한다. 산소와 레이더는 실제 터치 조작 영역을 피해 배치한다. 빈 백팩에는 별도 대응을 추가하지 않는다. 채팅은 유지하되 열렸을 때 자원 행을 창 아래로 옮긴다. 메뉴에는 `메뉴를 열어도 팀 시간은 계속 흐릅니다`를 표시한다. 캐릭터 리셋은 `기지로 구조 요청`과 같은 동작으로 통일해 산소 고갈과 동일한 식량 1, 물 2 비용을 안내하고 서버에서 처리한다. 기본 메뉴, 채팅, 터치 이동과 점프를 켠 상태로 검사한다. [Roblox 화면 컨테이너와 기본 UI 문서](https://create.roblox.com/docs/ui/on-screen-containers)
- 예상 작업량: M, 반나절, 리셋 동작 통합 포함

### 화면별 위치

HUD 좌표는 HUD의 유효 화면 원점을 기준으로 계산했다. HUD는 inset을 보존하므로 실제 디스플레이의 y에는 플랫폼 안전 영역이 더해진다. 화면을 꽉 채우는 레이더와 산소 GUI와의 y 원점도 같다고 가정하면 안 된다.

| 영역 | 1280x720 | 844x390 모바일 가로 | 667x375 모바일 가로 |
|---|---|---|---|
| 자원 | x=12-248, y=12부터 약 106px 높이 | 동일 | 동일 |
| 중앙 미션 영역 | x=410-870, y=10부터 자동 높이 | x=192-652 | x=103.5-563.5 |
| 오른쪽 패널과 탱크 | x=1008-1268, y=12부터 약 70px 높이 | x=572-832 | x=395-655 |
| 모듈 목록 | x=1008-1268, y=300-494 | x=572-832, 아래 최소 104px 이탈 | x=395-655, 아래 최소 119px 이탈 |
| 배속 버튼 | x=1196-1268, 화면 우하단 72x44 | x=660-732, y=10-54 | x=571.5-643.5, y=10-54 |
| 토스트 | x=968-1268, y=100부터 자동 높이 | x=532-832 | x=355-655 |
| 레이더 | x=16-196, y=498-704 | x=12-192, y=128-334 | x=12-192, y=128-334 |
| 산소 바 | x=470-810, y=672-702 | x=252-592, y=342-372 | x=163.5-503.5, y=327-357 |

1280x720의 상단 세 영역은 사각형끼리 겹치지 않는다. PC에서도 날짜 28px가 미션 17px보다 크고 밝으며, 즉시 행동은 흐린 보조색이다. 오른쪽 정보와 모듈 상태는 지속 노출되지만 목표 위치는 없어 `무엇을 어디서 할지`를 2초 안에 읽는 구조가 아니다. 모바일은 844px에서 중앙 영역과 좌우 패널이 각각 56px, 80px 겹치고, 667px에서는 144.5px, 168.5px 겹친다. 화면 폭이 1004px보다 작아지면 현재 세 상단 영역을 모두 분리할 수 없다.

착륙지 선택은 844x390에서 UIScale=0.75, 설명 15px가 실효 11.25px, 본문 17px가 12.75px, 버튼 44px가 33px가 된다. 667x375에서는 약 0.721배, 설명 10.82px, 본문 12.26px, 버튼 31.73px다. 최소 글자 14라는 주석만으로 모바일 가독성을 보장할 수 없다. 실제 프리셋 최소는 15이고, 스케일 적용 뒤에는 그보다 작다.

## 부록 C. 생존 피드백의 현재 상태와 최소 수정

| 상황 | 현재 시각 피드백 | 현재 청각 피드백 | 가장 작은 수정 |
|---|---|---|---|
| 자원이 감소함 | 재고 숫자 갱신, 지난 틱 순감소를 빨강과 음수로 표시 | 없음 | 0.4초 값 변화 강조, 건설 차감은 `물 -20, 착공` 원인을 붙임, 매일 소비음은 넣지 않음 |
| 전력 부족으로 시설 정지 | 진입 때 3초 토스트, 지속 상태는 가동 중으로 남음 | 없음 | 시설 행과 패드에 사유를 고정, 정지 진입 때 경고음 1회 |
| 물 부족으로 농장 생산 0 | 식량 순감소, 물 0이면 일반 부족 배너 | 없음 | 농장에 `물 부족, 생산 0` 표시, 원정 권고를 먼저 켬 |
| 식량이 3일 뒤 0 예상 | 별도 사전 경고 없음 | 없음 | 식량 행과 미션 아래에 `식량 약 3일분` 고정, 경고음 1회, 농장 준비는 7일분부터 유도 |
| 산소 20 이하 | 산소 바 0.35초 왕복 투명도 변화, 하단 에어락 안내, 서버 일회 경고 토스트 | 없음 | `실외 약 12초 남음`과 가장 가까운 유효 회복 지점 표시, 저음량 경고음, 선택적으로 약한 비네트 |
| 얼음 발견과 만충 | 범위 안 점이 커지고 파랑으로 변함, 만충 토스트 | 없음 | 범위 진입음과 만충 확인음 각 1회, 만충이면 귀환 표시로 전환 |

산소 20은 실외에서 `20 / (100/60) = 12초`다. 현재 안내의 에어락만 고집하면 바로 옆 로버의 회복 수단을 놓칠 수 있다. 로버 탑승과 실내를 모두 inside=true로 받아 산소 UI에 `에어락`이라고 표시하는 점도 고친다. 태그는 공통 `산소 회복 중`, 필요하면 실제 장소 이름을 추가한다. 경고음은 업로드와 재생 권한이 확인된 짧은 Sound 에셋을 한곳에서 사용하고, 화면 문구를 반드시 병행한다.

## 부록 D. 온보딩 흐름 재설계안

다음은 실제 삽입할 한국어 문장이다. PC 표기를 기본으로 쓰고 입력 토큰은 터치와 게임패드에 맞게 치환한다. 팀 자원 행동은 서버 상태로 확인하고, 개인의 탑승 여부와 조작 도움말은 로컬 상태로 분기한다. 첫 물 원정과 A 착공까지는 1배속을 유지한다. 목표 안내는 아래 완료 조건이 성립할 때만 다음으로 넘어간다.
