# 07 UI 배치 검토 (HUD, 2026-10-18)

검토 범위: src/client 전 모듈의 코드 좌표(AnchorPoint, Position, Size)를 화면 좌표로 환산. 실기 스크린샷 없이 코드 기준.
전제: HUD와 Toasts는 IgnoreGuiInset=false라 Roblox 상단바 인셋(현재 58px) 아래부터 그려지고, Radar, Oxygen, Tip, RoverBoost는 화면 맨 위가 0이다. 아래 숫자는 모두 화면 좌표(px). 패널 높이는 행 크기 합으로 추정했다.
Tip 카드는 이번에 산소 바 위로 옮긴 위치(TipUI.luau)로 표기한다.

## 2. 판정

- PC(1280x720, 1920x1080): 큰 틀은 유지한다. 읽는 순서(상단 중앙 목표, 좌상단 자원, 우측 진행, 하단 중앙 생명 수치와 Tip)가 장르 관습과 맞다. 다만 토스트가 우상단 패널과 겹치는 문제는 데모 전에 고친다.
- 휴대폰: 데모 수준이 아니다. 상단 3개 패널이 서로 겹치고 모듈 패널이 화면 밖이다. 해커톤 시연을 PC로 한다면 아래 2~4번만 손보고 나머지는 이후로 미룬다.
- 1920x1080은 모든 크기가 오프셋 고정이라 HUD가 작게 보이지만 겹침은 없다.

## 3. 권고 (우선순위 순, 최대 8개)

1. **토스트를 우상단 패널 실제 하단에 붙이기** - 지금(S)
   - 문제: 겹침. 토스트 y=100(인셋 기준)은 패널 높이 74를 가정했지만 배터리 행이 보이면 패널 하단이 ~118, 탑승 중이면 ~158이 된다. 모든 해상도에서 토스트가 배터리, 부스트 게이지를 30~70px 가린다.
   - 방법: HUD의 TopRight 프레임 AbsoluteSize 변경 신호에서 토스트 컨테이너 y = 패널 하단 + 8로 갱신(HUD가 프레임 참조를 노출). 토스트 3개 스택(~130px)이 모듈 패널(y 300)과 닿으면 2번과 함께 처리.

2. **모듈 패널을 좌측 열로 이동** - 데모 전(M)
   - 문제: 우측 열 과밀(패널, 토스트 3개, 모듈이 한 열에서 경쟁)과 휴대폰에서 모듈이 화면 밖.
   - 방법: 모듈 패널을 자원 패널 바로 아래(x 12, y 자원 하단 + 8, 폭 330)로. 720p에서 y 126~320(인셋 기준)이라 레이더(화면 y 478~)와 닿지 않는다. 우측 열은 상태(패널, 로버)와 사건(토스트)만 남아 읽는 순서가 정리된다.

3. **휴대폰 압축 배치(UIScale 0.7 + 상단 재배치)** - 데모 전(M)
   - 문제: 휴대폰 겹침, 화면 점유율.
   - 방법: 터치 전용이고 화면 높이 500 미만이면 HUD 각 최상위 프레임에 UIScale 0.7. Day 패널 폭 460 -> 320(스케일 후 224). 그러면 자원 12~243, Day 310~534, 패널 650~832로 상단 겹침이 사라진다. 모듈은 A/B/C 칩 3개 한 줄(각 64x28)로 접어 Day 패널 아래에 둔다. 배속 버튼은 패널(우상단) 아래로.

4. **레이더와 부스터 버튼의 인셋 기준 통일 + 부스터를 오른손 쪽으로** - 지금(S) / 부스터 이동은 데모 전(M)
   - 문제: 겹침과 엄지 동선. 레이더(y 128)와 부스터(y 154)는 인셋을 무시해 자원 패널(실제 y 70~176)과 겹친다. 부스터는 왼손 엄지가 조이스틱을 잡고 있는 동안 같은 왼쪽 위에 있어 누르기 어렵다.
   - 방법: 레이더 y를 자원 패널 실제 하단 + 8로 계산(GuiService:GetGuiInset 반영), 휴대폰에서는 레이더 크기 180 -> 140. 부스터 버튼은 점프 버튼 위(Anchor 1,1, Position (1,-24,1,-110), 크기 96x64)로 옮겨 오른손 엄지로 점프와 함께 누르게 한다.

5. **글자 크기 하한 14 적용** - 지금(S)
   - 문제: 글자 크기. UI.TextStyles는 최소 14를 정했지만 HUD 남은 일수, 배터리 배지, 부스트 캡션이 12, 레이더 매장량 숫자가 11이다. 휴대폰과 프로젝터 시연에서 읽히지 않는다.
   - 방법: 12 -> 14, 11 -> 13. 배지 폭 62 -> 72.

6. **색 의미 충돌 정리** - 지금(S)
   - 문제: 색 의미 충돌. 레이더의 바위밭 얼음 점(255,150,50)이 산소 주황과 같은 값이다. 실내 표시 "에어락" 태그와 착륙지 이름, 레이더 거리 글씨가 물 하늘색을 쓴다. 부스터 버튼 테두리가 산소 주황인데 실제로는 배터리(에너지)를 쓴다.
   - 방법: 바위밭 얼음 점은 보라(190,120,255), 에어락 태그는 good 초록(안전), 착륙지 이름은 textDim, 부스터 테두리는 energy 노랑. 이후 주황은 산소, 하늘색은 물에만 쓴다.

7. **해상도 비례 스케일(PC 고해상도)** - 이후(L)
   - 문제: 1920x1080 이상에서 HUD가 작아 텍스트가 상대적으로 작다(자원 패널이 화면 폭의 17%).
   - 방법: 3번의 UIScale을 공통화해 scale = clamp(화면 높이 / 720, 0.7, 1.25). 1080p에서 1.25. Tip의 하단 여백 84와 좌측 경계 248도 같은 배율로 계산.

8. **월드 프롬프트와 하단 Tip의 수직 여유 확인** - 이후(L)
   - 문제: 겹침 가능성. 바닥 가까운 대상(패널 슬롯, 얼음)에 바짝 붙으면 프롬프트 패널(앵커 아래로 72+10px)이 화면 80% 높이까지 내려올 수 있어 Tip(1080p 기준 84~92%)과 닿을 수 있다.
   - 방법: 플레이테스트에서 확인 후 필요하면 PromptUI의 패널을 앵커 위쪽으로 뻗게 하거나 Tip 표시 중 프롬프트 STACK을 위로 올린다.

## 4. 이번에 반영한 것 (Tip 카드)

- 위치: 화면 중앙 65% -> 하단 중앙, 카드 아래 끝이 화면 하단에서 84px(산소 바와 에어락 태그 위 8px). AnchorPoint (0.5, 1)이라 3줄이 되어도 위로만 자란다.
- 폭: 최대 560. 레이더 오른쪽(x 248) 안쪽으로 들어가면 오른쪽으로 비키고, 터치는 점프 버튼 몫 120px를 남긴다. 휴대폰 844x390에서 폭 476, x 248~724.
- 연출: 아래에서 24px 올라오며 0.3초 페이드 인, 6초 유지, 12px 가라앉으며 0.5초 페이드 아웃. 크림 카드와 문구는 그대로.
- GDD의 Tip 카드 절에 남은 "화면 중앙 세로 65% 지점" 문구는 갱신이 필요하다.

## 5. 14차 반영

- 증상: PC(뷰포트 약 2207x1244)에서 HUD는 PC 배치인데 레이더만 compact 크기(140)로 모듈 패널 위에 겹쳐 그려졌고, 거리 문구가 가운데 정렬로 레이더 폭을 넘어 왼쪽이 잘렸다.
- 원인: RadarUI와 ToastUI가 init 시점에 한 번만 compact를 판정했다. 그 시점의 CurrentCamera.ViewportSize가 아직 작거나 0이라 compact로 굳어졌다. HUD는 Layout.changed로 다시 적용해 문제가 없었다.
- 조치: Layout.viewportSize는 카메라가 없거나 높이가 200 미만이면 1280x720으로 본다. RadarUI는 applyLayout(compact)로 크기, 위치, 라벨 폭을 한 번에 갱신하고 init, Layout.changed, step에서 다시 적용한다(PC 좌하단 180, compact 자원 패널 아래 140). 거리와 배터리 문구는 왼쪽 정렬, 폭 레이더 지름 + 140, 거리는 한 줄 말줄임, 배터리는 2줄. ToastUI는 0.2초 루프에서 매번 compact를 읽어 위치와 폭, 최대 개수를 정한다.
- Tip 카드: 사용자 결정으로 우측 하단으로 이동. PC는 오른쪽 16px, 아래 16px, 폭 360. compact는 오른쪽 12px, 아래 190px(부스터 버튼 위), 폭 min(360, 뷰포트 폭 - 24). 레이더와 산소 바 회피 로직은 제거했다.
