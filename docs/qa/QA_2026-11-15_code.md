## A8 상세 (파견 시간 규칙과 밸런스)
- 서버는 하루의 절반이 지난 뒤 파견하면 `trip.elapsed = -1`로 시작한다(귀환이 하루 늦어짐). 하루가 절반 넘게 남았을 때 보내면 elapsed 0. 의도: 하루 마감 직전에 보내면 1일 왕복이 2초 만에 돌아오던 문제(2026-11-15 플레이 테스트) 수정.
- 봇 시뮬레이션과 BALANCE_LOG는 모든 파견을 elapsed 0으로 계산한다. 파견 시각이 하루 안에서 고르다고 가정하고(절반 확률로 elapsed -1) 같은 봇, 같은 시드로 돌려 비교했다(실제 DONKI 5구간 x 시드 200, 실패/동/은/금 %):

| 파견 규칙 | 솔로 처음 | 솔로 두 번째 |
|---|---|---|
| 시뮬레이션 가정(항상 elapsed 0) | 30 / 36 / 33 / 0 | 16 / 46 / 32 / 6 |
| 현재 서버(0.5, 절반 확률로 -1) | 34 / 13 / 53 / 0 | 17 / 19 / 59 / 6 |
| 항상 -1(dispatchDayMinLeft 1이었을 때) | 37 / 4 / 59 / 0 | 22 / 4 / 69 / 6 |

- 읽는 법: 사용자가 확정한 분포(BALANCE_LOG 7.5.1, 8.7: 솔로 처음 29/39/32/0)에서 동메달이 크게 줄고 은메달이 늘며 실패는 조금 늘어난다. 파견이 늦어져 물 도착이 미뤄지고, 대신 로버 에너지 지출이 줄어 업그레이드로 돌린다는 해석(추정, 봇 내부는 따로 분해하지 않음). 파견 시각 분포는 사람 실측이 아니라 내 가정이다.
- 화면의 "왕복 약 N일"도 실제로는 N일 +- 반나절(1일 왕복이 15 ~ 45초)이다.
- 제안: Studio 실측(BALANCE_LOG 7.6)과 함께 파견 시각을 기록하거나, 봇의 파견에 elapsed -1 확률을 넣어 다시 맞추고 문서(CONTRACT_V2 9절, BALANCE_LOG 8절)에 적는다.
